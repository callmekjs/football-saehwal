>
> **여기는 목록이고 일지가 아니다.** "지금 무엇이 고장나 있나"를 한 화면에서
> 읽는 곳이다. 언제 어떻게 찾았는지 같은 이야기는 원본 문서에 있고 맨 아래에
> 어디를 봐야 하는지 적어 뒀다.

## 왜 이 파일이 생겼나

오류가 **네 문서에 흩어져 있었다.** QA가 찾은 것은 `qa-log.md`, 최종 평가가
찾은 것은 `HANDOFF.md`, 사용자가 화면을 보고 지적한 것은 `progress.md`,
되돌린 시도는 `worklog.md` 다. 네 개를 합치면 40만 자가 넘는다.

그래서 실제로 사고가 났다. `qa-log.md` 의 종합표는 QA-15·16을 「미수정」으로
적고 있는데 그 표를 만든 뒤에 들어간 커밋이 둘 다 고쳤다. 다음 사람이 이미
끝난 일을 다시 조사했다. **표가 낡으면 없는 것보다 나쁘다.**

## 읽는 법 — 세 줄

- **아직 고장나 있는 것**만 보려면 1번 절만 읽으면 된다.
- **고치기 전에** 2번(사람이 정할 것)과 5번(다시 시도하면 안 되는 것)을 본다.
- 고친 것은 3·4번에 있다. **거기 있는 것을 다시 보고하지 않는다.**

한 줄에 **근거**를 같이 적었다. 「고쳤다」가 아니라 「어느 커밋에서 고쳤고
어느 회차가 다시 확인했나」다. 근거 없는 줄은 이 파일에 넣지 않는다.

### 1-1. 화면의 「실측」 숫자가 실측과 다르다

국면 고르는 화면에 「미국 상대 · 1,200시드 실측」이라는 딱지를 달고 뜨는
숫자다. **실측이라고 적힌 숫자가 실측과 다르다.**

```text
코드   0.109 / 0.495 / 0.493 / 0.378 / 0.183
실측   0.107 / 0.480 / 0.468 / 0.370 / 0.195   (8/1 npm run sim)
차이   +0.2 / +1.5 / +2.5 / +0.8 / -1.2 %p
```

첫 화면 아래 흐르는 띠의 「기준팀 무개입 통과율 11.1~48.9%」도 양끝이 다
틀리다(실측 10.7~48.0%). 표를 만든 뒤 엔진에 두 커밋이 들어가서 낡았다.

**13개 팀 줄이 전부 의심 대상이라 기준팀만 재면 나머지 12줄이 낡은 채
남는다.** `npm run sim -- --team=ALL` 이 80분 걸리고 그 동안 아무도
`src/sim` 을 만지면 안 된다. 그래서 배포 뒤로 미뤄 뒀다.

### 1-2. 뜬 공의 공기 저항 (10번)

구르는 공은 8/1에 고쳤다 — 항력이 속도의 **제곱**이 됐다. **공중에 뜬 공은
아직 속도에 비례하는 옛 모양**이고 계수도 1초에 5%로 사실상 없는 것과 같다
(`AIR_DRAG = 0.05`). 초속 25미터의 롱볼은 실제로 1초에 33%를 잃는다.

**같이 안 고친 이유가 있다.** 뜬 공의 감속을 바꾸면 공이 **어디에 떨어지는지**가
바뀐다. 롱패스의 체공 시간을 정하는 `loftFor()` 가 수평 속도가 일정하다고
보고 계산하므로, 항력을 세게 걸면 롱볼이 죄다 짧게 떨어져 배후 침투와 롱패스가
통째로 무너진다. 고치려면 `loftFor` 를 함께 풀어야 하고, 그 다음 골 장면
비율(지금 100%)과 패스 성공률(지금 77.7%)을 다시 재야 한다.

**한 번에 하나씩 고친다.** 구르는 공과 뜬 공을 같이 바꾸면 무엇이 무엇을
망가뜨렸는지 알 수 없다.

## 5. 다시 시도하면 안 되는 것 — 재봤고 되돌렸다

**여기 있는 것은 「아직 안 해본 좋은 생각」이 아니다.** 실제로 해보고
숫자를 재고 되돌린 것이다. 다시 하면 같은 자리로 돌아온다.

| 시도했던 것 | 왜 되돌렸나 |
|---|---|
| **하프타임 회복을 「쓴 양」으로 자르기** | 덜 뛴 선수가 **더 적게** 회복하게 되어 사용자 규칙을 정반대로 깬다 |
| **패스 조준 자체를 올리기** | 정확해질수록 공이 마크맨에게 정확히 간다. 조준 84.1%인데 최종 성공률은 **내려갔다**. 실측이 `pass()` 주석에 있다 |
| **골 빈도 낮추기** | 7/29에 해봤다. 근거와 되돌린 이유가 `HANDOFF.md` 「골 빈도를 낮추려다 되돌린 기록」에 있다 |
| **첫 화면 점들을 제자리에서 떨게 하기** | 살아 있는 것이 아니었다. 공이 없는 스물한 명이 움직이는 이유는 공의 위치 하나다 |
| **스로인·골킥·코너킥에도 전원 정지** | 우리 팀 박스 안 공격 판단이 150판에 25회 → **6회**로 사라진다 |
| **자유 배치를 위·아래 두 지시로 되돌리기** | 요구 자체를 잘못 정의한 것이었다. `worklog.md` 와 QA-06을 읽어라 |
| **관전 속도 기울기 0.6** | 빨라진 수비가 예약 골 장면을 가로채 80골 중 셋이 장면 없이 지나갔다. 0.45로 낮춰 해결 |
| **`SAME_MATCH_WINDOW_MS` 를 늘려 반복 저장 가리기** | 루프는 그대로 돌고 CPU 만 계속 먹는다. 증상만 가리는 것이다 |
| **분석 빗장을 「붙는 순간 한 번」으로 걸기** | 앱이 `StrictMode` 안에서 돌아 효과를 붙였다 떼었다 다시 붙인다. 두 번째가 걸려 **분석이 아예 안 돌고 화면이 영원히 「검증 중…」에 머문다** |
| **구르는 공과 뜬 공의 항력을 한 번에 바꾸기** | 뜬 공을 건드리면 `loftFor()` 가 함께 무너져 롱볼이 죄다 짧게 떨어진다. 무엇이 무엇을 망가뜨렸는지 알 수 없게 된다 |
| **박스 안 슛 확률을 70%로 낮추기** | 박스 안은 이미 96.2%다. 낮추면 요구와 반대 방향이 된다. 문제는 박스 **바깥** 16.5~25m 였다 |
| **직전 프레임의 공 주인으로 「누가 찼나」를 재기** | 0.1초 안에 소유가 바뀌면 그 사람은 찬 사람이 아니다. `ball.fromX`·`ball.lastTouch` 로 재라. 이 오차가 백패스를 27%로 부풀렸다 |

## 6. 알면서 안 고친 것 — 구조상 큰 것

**다시 보고하지 마라.** 고치려면 밸런스를 처음부터 다시 재야 하는 것들이다.
지금 「길이 막혔다」의 격차가 합격선까지 **0.5%p**, 「잠긴 문」 무개입이
천장까지 **2.0%p** 밖에 없다.

| 항목 | 이유 |
|---|---|
| **골이 실제보다 2.1배 많다** (90분 환산 5.73골, 실제 2.5~2.8) | 줄이려다 되돌렸다. 5번 절을 보라 |
| 코너킥 판당 0.1회 (실제 1.7회) | 걷어내기와 굴절이 없어 공이 자기 골라인 밖으로 안 나간다 |
| 오프사이드 라인이 박스 밖 83~86m에 머문다 | 우리 수비 블록이 자기 골대까지 안 물러난다. 고치려면 압박·태클·실점 연출을 통째로 다시 재야 한다 |
| 예약된 골이 있으면 오프사이드를 안 분다 | 규칙에 없는 예외지만, **시뮬이 골이라고 했는데 화면이 안 보여주는 것이 더 큰 고장**이다 |
| 상대 대형이 확률을 가르지 않는다 | 대형은 성향과 짝지어 뽑고 화면·브리핑만 읽는다 |
| 상대 부상·경고가 상대 인원을 줄이지 않는다 | 화면이 한 명을 빼면 점수판·브리핑·보고서가 서로 다른 인원을 말한다 |
| 물러서라·아껴 뛰어라 효과 +1%p 천장 | 시뮬이 인원 변화와 체력을 실점에 안 센다 |

| 미국(16위) 평균 능력치 11.9 < 일본(17위) 13.9 | 미국이 기준팀이라 계수가 0이어서 생기는 순서 역전 |

## 7. 이 파일을 어떻게 유지하나

**고친 사람이 같은 커밋에서 여기도 옮긴다.** 1번 절의 줄을 3번이나 4번으로
옮기고 근거(커밋 해시 또는 재확인한 회차)를 적는다. 이 한 줄을 빼먹으면
다음 사람이 끝난 일을 다시 조사한다 — 실제로 그렇게 됐다.

**새 결함은 1번 절에 값어치 순으로 넣는다.** QA가 찾은 것이면 `qa-log.md` 에
회차 기록을 남기고 여기에는 한 줄만 적는다. **긴 이야기를 여기 쓰지 마라 —
이 파일이 길어지면 아무도 안 읽고, 그러면 흩어져 있던 때로 돌아간다.**
