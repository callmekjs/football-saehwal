## ★★ 0. 제일 먼저 조사할 것 — 기준선이 밀렸다 ★★

**개별 지시 작업(아래 ⓐ)이 들어간 뒤 `npm run sim` 을 돌렸더니 다섯 국면이
전부 합격이고 지시 효과도 살아났다. 그런데 무개입 통과율이 움직였다.**

```
「한 명이 많다」  무개입 18.3% → 18.8%   격차 25.1 → 25.2%p
```

합격선(50% 이하)에는 한참 못 미치므로 **탈락 위험은 없다.** 하지만 이
저장소의 규칙은 「한 자리라도 움직이면 회귀」다. 무개입은 **지시를 하나도
안 준 상태**이므로, 지시 계수를 아무리 바꿔도 움직이면 안 된다.

**의심할 곳 둘.**

1. **`NONE` 일 때 모든 계수가 정확히 1.0 인가.** `src/sim/types.ts` 253줄
   부근 주석이 이것을 요구한다. 지시가 하나도 없는 경기는 이 기능이 생기기
   전과 **비트 단위로 같은 결과**를 내야 한다
2. **난수 소비가 늘었는가.** `drawTick()` 은 매 틱 정확히 18개다. 조건
   분기 안에서 뽑으면 수열이 밀린다

`src/sim/tactics.ts` 의 `applyOrders()` 가 지시 없을 때 **기존 계수 객체를
그대로 반환**하는지 먼저 봐라. 새 필드를 더하면서 새 객체를 만들면 값이
같아도 부동소수 연산 순서가 달라져 결과가 밀릴 수 있다.

**나머지 네 국면의 숫자는 확인하지 못했다** — 배경 실행의 출력 끝부분만
남아서 「한 명이 많다」만 보였다. `npm run sim` 을 다시 돌려 다섯 개를 전부
기준선과 대조해라.

  읽힌다. 같은 판이어야 **딱 하나 다른 것이 판단**임이 눈에 보인다
- 재료는 이미 있다 — `src/data/problems.json` 의 `recommendation`(국면마다

  시뮬레이션의 핵심 주장이 "옳게 판단하고도 무너질 수 있다"이다
- **「AI가 플레이한다」고 쓰지 마라.** 즉흥으로 두는 AI 가 아니라 **시드
  1,200개로 검증한 최선의 설정**이다. 그게 훨씬 강한 주장이고 사실이다
