## 지시별 실측 효과 — 정직하게

| 지시 | 실제 효과 |
|---|---|
| 골문 앞 | 지키는 판 +3.9~4.5%p · 쫓는 판 −1.6%p. **작동한다** |
| 내려서라 ×2 / ×3 | 지키는 판 +4.7~6.8 / **+7.1~9.9%p**. 쫓는 판 −1%p. **작동한다** |
| 올라가라 ×2 / ×3 | 지키는 판 −6.4~7.1 / **−10%p**. 쫓는 판 +1.0~1.4%p |
| 물러서라 · 아껴 뛰어라 | **최대로 키워도 +1%p가 한계다** |

**왜 둘이 안 먹는가 — 지시가 약해서가 아니라 시뮬이 그걸 안 세기 때문이다.**
퇴장해서 9명이 되어도 10명과 똑같이 계산하고, 체력은 실점에 아예 반영되지 않는다.
고치려면 밸런스를 처음부터 다시 재야 해서 손대지 않았다.

**실점 채널 구성: 세트피스 61% · 오픈플레이 27% · 배후 9%.**
개별 선수 지시가 판을 움직이려면 **세트피스 채널을 타야 한다.** 배후만 건드리면
9%짜리를 5% 깎는 것이라 전체로는 0.5%이고 오차에 묻힌다. 실제로 한 번 그렇게
만들었다가 세 국면 전부 오차 안으로 나와 갈아엎었다.

배치 원칙뿐이다** — 실존 선수 이름·구단·엠블럼·색·아이콘·컴포넌트는 하나도
가져오지 않았다. 우리 선수는 여전히 등번호만 쓴다.

**넓은 화면(1240px 이상)은 세 열이다.**

| 열 | 들어간 것 |
|---|---|
| 왼쪽 | 우리 전술판(포메이션 9칩 + 선수 11명) · 벤치·교체 |
| 가운데 | 경기 기록 \| 경기 이벤트 · **큰 경기장** · 전술 프리셋 5 + 레버 |
| 오른쪽 | 상대 포메이션(읽기 전용) · 급수 타임 / 진행 요약 / 결과 패널 |

**왼쪽 전술판이 조작 수단이다.** 선수 카드를 누르면 그 선수에게 지시를 건다
(`src/ui/SquadPanel.tsx`). 문법은 **선수 1탭 → 행동 1탭**이고, 7/29부터
**마우스로 끌어다 놓는 빠른 길이 하나 더 생겼다**(아래 "선수 카드 드래그"
참조). 탭 두 단계는 그대로 살아 있다 — 드래그는 유일한 길이 아니다.
카드는 44×44px 표적이다. 포메이션을 바꾸면 카드가 새 자리로 움직여서,
그동안 화면에서 잘 안 읽히던 포메이션 변경이 눈에 보인다.

- 자리 배정 규칙은 `src/render/visual.ts`와 **같다** — 뛰던 선수는 쓰던 자리를
  지키고 빈자리는 포지션이 맞는 새 선수가 받는다. 옆 판과 경기장이 서로 다른
  자리를 가리키면 둘 중 하나가 거짓말이 된다.
- 급수 타임과 경기 중 모두 조작되고, 끝난 뒤(`DONE`)에만 닫힌다.
- **선수 평점은 없으므로 만들지 않았다.** 그 자리에 체력 막대와 지시 상태,
  그리고 경고·지침·위험 꼬리표를 넣었다.

## 급수 타임 주장 브리핑 — 7/29 완료

사용자 아이디어다. "하이드레이션 브레이크 때 감독이 경험할 수 있는 걸
사용자가 경험하게" 하는 것으로, 킥오프 전 안내문 자리를 **주장의 말**로
바꿨다.

- 문장은 `src/analysis/briefing.ts` 의 **순수 함수**가 만든다.
  `buildBriefing(problem, state)` → `{ speaker, core, more }`.
- **없는 값을 만들지 않는다.** 전부 `problems.json` · `MatchState` ·
  `squads.json` · `constants.ts` 에서 계산한다. 해당 없는 항목은 아예
  나오지 않는다(경고 보유자 없으면 퇴장 얘기 없음).
- **판마다 컨디션 보고 하나가 바뀐다.** 팀 전체·수비진·중원과 공격진의
  회복/피로 여섯 종류다. 같은 시드는 같은 보고가 나온다.
- 컨디션 보고는 문구만 바꾸지 않는다. 팀 전체는 시작 체력 ±6, 줄별은
  ±10이 실제 선수 상태에 반영된다. 벤치는 제외하며, 개별 지시로 줄을
  옮긴 선수는 현재 줄(`effectivePos`)을 기준으로 묶는다.
- 이 보고만 쓰는 전용 난수 스트림이 있다. 경기의 매 틱 18개와 기존
  시작 체력·경고·지시의 난수 소비 순서는 건드리지 않는다.
- **답을 주지 않는다.** "15번을 넣으세요"가 아니라 "15번이 81, 지금 뒷선
  최저가 62"까지다. 명령형 문구가 없다는 것을 테스트가 지킨다.
- 할 말이 10~14줄이라 **급한 넷만 보이고 나머지는 `<details>` 로 접었다.**
  펼친 목록은 208px 안에서 굴러서 오른쪽 열이 통째로 길어지지 않는다.
- 우선순위: 점수·목표 → 우리 인원 → 팀 컨디션 → 퇴장 위험 → 부상 임계 → 상대 성향 →
  최고 위협 선수 → 체력 → 경고 → 라인의 대가 → 물려받은 설정 →
  피치 위 최고 마무리 → 벤치 자원 → 남은 교체.
  **지키는 판은 벤치 수비수가, 쫓는 판은 벤치 마무리가 먼저 나온다.**
- 주장이 누구인지는 데이터에 없다. 지어내지 않고 **규칙을 정했다** —
  피치 위 필드 플레이어 중 등번호가 가장 작은 선수. 세 국면 모두 2번.
- 전술 프리셋 표를 `src/analysis/presets.ts` 로 옮겨 화면과 브리핑이 같은
  표를 본다. 나뉘어 있으면 화면은 "역습"인데 주장은 "직접 맞춤"이라고
  말하게 된다.
- 자리는 상대 판에서 가져왔다. `.squad-shape.away` 최소 높이 356 → 240.
  356은 **44px 손가락 표적** 기준인데 상대 카드는 누를 수 없는 38px 이다.
  실측 세로 최소 간격 12px, 겹침 0.
- 1512×900 준비 화면: 문서 높이 900 → 932, 경기 재개 버튼 아래 끝 893
  (첫 화면 안), 경기장 762×493 그대로, 가로 넘침 0.
- 375×812: 가로 넘침 0, 첫 전술 버튼 478px 그대로, 문서 높이 1067 → 1201.
- 테스트 17개 추가(207 → 224). `src/sim/`·`src/render/`·`balance/` 변경 0줄.

## 급수 타임 음성 지시 — 7/29 완료

같은 사용자 아이디어의 두 번째 갈래("음성으로도 되고").

- **음성은 덤이다.** 탭으로 하던 모든 것이 그대로 남는다. 세 갈래를 전부
  강제해서 확인했다 — 정상(문서 939) · 권한 거절(919) · 지원 안 함(**900**,
  기준선과 동일). 어느 경우에도 전술 5·선수 11·벤치 5 조작이 그대로다.
- **급수 타임에서만.** 경기 중에는 안 쓴다. 잘못 알아들었을 때 되돌릴
  방법이 없기 때문이다. 휘슬이 울리면 마이크를 놓는다.
- **누르고 있는 동안만 듣는다**(`onPointerDown`/`Up`/`Leave`/`Cancel`).
  항상 켜두면 혼잣말이 지시가 된다.
- **키가 필요 없다.** `window.SpeechRecognition || webkitSpeechRecognition`
  은 브라우저 기본 기능이다. **외부 서비스를 붙이지 마라** — 키가 필요한
  기능은 대회 평가에서 빠질 수 있다.
- 알아듣는 말은 정해져 있다(`src/ui/voice.ts` 의 `parseCommand`, 순수 함수).
  선수 지시 5종 + 취소, 전술 프리셋 5종, 포메이션 9종.
  포메이션 숫자는 "442" · "4 4 2" · "4-4-2" · "사사이" 를 하나로 눕힌다.
- **한자어 숫자는 아라비아 숫자가 하나도 없을 때만 읽는다.** 안 그러면
  "포메이션 442로"의 **포메이**에서 이(2)를 주워 2442가 된다. 붙어 있는
  덩어리 중 가장 긴 것만 본다.
- **못 알아들으면 아무것도 하지 않는다.** "다시 말씀해 주세요"만 띄운다.
  엉뚱한 지시를 거는 것이 못 알아듣는 것보다 훨씬 나쁘다.
- 들은 말과 한 일을 둘 다 보여준다. 자리를 늘 잡아 두어 글자가 떠도 아래
  버튼이 밀리지 않고, 아직 말하기 전에는 그 자리에 예시가 들어간다.
- 막힌 이유는 탭으로 눌렀을 때와 **같은 문장**이다 — `checkOrder` 를
  그대로 쓴다. 검증을 새로 만들지 않았다.
- `src/ui/useVoice.ts` 가 브라우저 API를 감싸고, `src/ui/voice.ts` 는
  순수해서 테스트가 붙는다(13개, 총 237개).
- **이 환경에서는 마이크 권한을 받을 수 없어 실제 목소리 인식은 확인하지
  못했다.** 브라우저가 부르는 것과 같은 콜백을 흉내내 전 과정(들은 말 →
  해석 → 화면 반영)을 돌렸고, 실제 API의 권한 거절 경로는 확인했다.
  **폰 실기기 확인(9번) 때 목소리로 직접 눌러 봐야 한다.**

- 순수 함수는 `src/ui/squadDrag.ts`(`resolveDrop` · `swapSeats` ·
  `dropHint`), 배선은 `src/ui/SquadPanel.tsx`.
- **알아둘 것 — 자리 바꾸기는 전술판에만 반영된다.** 경기장 캔버스는
  `src/render/visual.ts` 가 자기 자리 배정을 따로 들고 있고 이번 작업에서

## 절대 어기면 안 되는 것

1. **`src/sim/` 은 브라우저를 모른다.** window·document·requestAnimationFrame·
   Date·Math.random 금지. 확인: `npx tsx -e "import('./src/sim/engine.ts')"`
2. **난수 소비 순서를 바꾸지 않는다.** `src/sim/attack.ts` 의 `drawTick()` 은 매 틱
   정확히 18개를 정해진 순서로 뽑는다. 순서를 바꾸면 저장된 모든 시드의 결과가
   달라져 밸런스를 처음부터 다시 재야 한다.
3. **실존 선수 이름을 넣지 않는다.** 대회 규칙이 실명을 금지하지는 않지만, 이
   시뮬레이션은 구조상 **"가장 느린 수비수"를 실점 원인으로 기계적으로 지목**한다.
   실명이 붙으면 "○○ 때문에 졌다"가 자동 생산되어 **특정 선수 비하 금지**에 걸린다.
   `Player` 타입에 name 칸 자체가 없고 `squad.test.ts` 가 막는다.
4. **확률 숫자는 `src/sim/constants.ts` 에만.** 포메이션 계수만 `formations.ts` 예외.
5. **지시가 하나도 없으면 모든 계수가 정확히 1.0이어야 한다.** 이 항등이 깨지면
   저장된 시드와 밸런스 기준선이 전부 죽는다. 계수를 만지기 전에 먼저 확인하라.
6. **폰이 기본.** 버튼 최소 44px. **작은 원 위에 드래그해서 놓는 방식은 쓰지 않는다.**
   폰에서 선수 원의 반지름은 7픽셀이라 손가락 표적이 못 된다.

## 작업 원칙 — 전부 실패해서 얻은 것이다

- **숫자를 추측으로 조정하지 말고 먼저 측정한다.** 이 프로젝트에서 추측 튜닝은
  네 번 실패했고 매번 원인이 다른 데 있었다.
- **낡은 측정값을 믿지 마라.** 다시 재보니 여섯 줄 중 다섯이 어긋나 있던 적이 있다.
  이미 해결된 증상에 시간을 쓰지 않으려면 자기 자로 먼저 찍어야 한다.
- **판별 최소차이는 약 4%p다** (시드 1200개, 표준오차 ±1.44%p).
  그보다 작은 효과는 있으나 마나다. 목표치를 그 위로 잡아라.
- **희소한 사건은 여러 판을 합쳐 잰다.** 부상은 200판을 돌려야 47회다.
- **데드볼 프레임은 속도·거리 지표에서 뺀다.** 안 빼면 멈춘 시간이 늘기만 해도
  지표가 좋아 보인다.
- **테스트에 조정 대상 숫자를 박지 않는다.** 방향과 비율로 쓴다.
- 진단 스크립트는 `balance/` 에 만들고 **커밋 전에 지운다.**
- 커밋 메시지는 한국어로, **왜** 그렇게 했는지에 지면을 쓴다.
- `docs/progress.md` 와 이 파일을 갱신한다.

## 외부 참고 — open-football (저작권 주의)

사용자가 https://github.com/ZOXEXIVO/open-football 를 참고하라고 했다.
**Apache License 2.0 · Rust.** 사용자 지시: **"100% 카피하는건 절대 안 돼."**

- **코드를 한 줄도 가져오지 않았다.** 저장소를 clone 하지 않았고 그쪽 파일을
  우리 폴더에 만들지 않았다. 자료구조·상수 표·주석을 옮겨 적은 곳이 없다.
- **가져온 것은 개념 한 문장뿐이다** — "지금 무엇을 하는 중인가가 속도 상한을 정한다."
  방법이지 표현이 아니라 저작권 대상이 아니다. 이름도 우리말로 다시 지었다.
- **그쪽 데이터베이스는 절대 쓰지 않는다.** 실존 구단·선수 실명이 들어 있고,
  우리 구조에 붙으면 비하 콘텐츠가 자동 생산된다. 사용자도 확인했다 —
  **"실제 선수들의 데이터들은 필요 없어. 어차피 선수들 데이터는 가상으로 만들 거니까."**
- 전술 어휘는 참고했다 — 팀 스타일 9종(압박·라인·밀집도 세 숫자로 정의),
  포메이션 14종, 개별 지시 8축(너비·깊이·슛 빈도·패스 위험·태클 강도·압박 강도·
  전담 마크·역할 변경). 이 중 우리에 맞는 것만 우리 체계로 새로 만들었다.
- **전담 마크는 안 가져왔다.** 실측으로 이득(behind ×0.85 = −1.3%)보다
  대가(oppOpen ×1.12 = +3.2%)가 커서 쓰면 손해였다.
