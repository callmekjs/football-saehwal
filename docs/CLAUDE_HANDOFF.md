## 프로젝트 한 문장

바둑의 사활 문제를 축구에 옮긴 실시간 감독 시뮬레이션이다. 한 국면의 경기
22분을 75초에 압축하고, 사용자가 포메이션·전술·선수 지시·교체를 선택한 뒤
종료 화면에서 더 나은 전술과 그 근거를 배운다.

사용자가 정한 표현:

- 제품을 **시뮬레이션**이라고 부른다.
- **퍼즐**이라고 부르지 않는다.
- 핵심은 제한 시간 안의 다양한 감독 개입과 경기 후 전술 학습이다.

### 3. 관전 연출

- 공 소유·패스·인터셉트·태클·슛·선방·골망·세리머니
- 킥오프·프리킥·스로인·골킥·코너킥
- 가속·감속·체공·튕김·마찰
- 교체·부상·퇴장·경고·체력 표시
- 시뮬 시계를 따라잡아 탭 전환이나 느린 프레임이 일시정지가 되지 않음
- 시뮬이 골을 정해도 실제 공격과 슛 장면이 만들어진 뒤 점수판이 올라감
- **주심 하나와 부심 둘.** 부심이 오프사이드 라인(뒤에서 두 번째 수비수)에
  서고, 둘이 서로 반대편 터치라인의 반대편 절반을 맡는다
- **오프사이드** — 깃발이 먼저 올라가고 공이 멎으면 휘슬이 분다. 판당
  0.63회로 실제 축구(0.7~1.0회)와 같은 자리다. 페널티 지역 안은 보지
  않는다(수비 블록이 자기 골대까지 안 물러나는 한계)
- **주심이 판정을 준다** — 반칙·페널티킥·오프사이드·킥오프는 주심 휘슬,
  스로인·코너킥·골킥은 부심 깃발이다. 경고·퇴장은 주심이 선수 앞까지 가서
  손에 카드를 든다. 실제 축구에서 스로인마다 휘슬이 울리지 않는다
- **오프사이드 라인이 실선으로 그려진다.** 수비하는 팀 색이고, 그 팀의
  뒤에서 두 번째 수비수를 지난다. 부심이 그 선 위에 서 있다. 하늘색
  점선(감독이 설정한 수비라인)과는 실선/점선·색으로 구분된다
- **그리기 자체를 검사하는 테스트가 생겼다**(`src/render/pitch.test.ts`).
  가짜 캔버스에 그려서 무엇을 어디에 어떤 색으로 그렸는지 확인한다.
  좌표 계산이 다 맞아도 화면 밖에 그리면 소용없다는 것을 실제로 겪었다

최근 수정:

- 공이 아웃되려는 중 예약 골이 만료되어 갑자기 실점으로 바뀌던 충돌을
  수정했다.
- 공이 0.5초 안에 라인을 벗어날 궤적이거나 아웃 재개 중이면 예약 골을
  실행하지 않는다.
- 720경기·886개 골 장면에서 세리머니와 아웃 재개의 동시 발생은 0개다.

### 5. 경기 종료 Coach 분석

- 무개입·사용자 판단·권장 전술을 같은 시드로 150경기씩 비교
- 한 경기의 운과 판단의 품질을 분리
- 득점·실점 시각, 발생 경로, 당시 전술, 확신도와 근거 표시
- 150경기 평균 득점·실점·슈팅·세트피스·배후 침투 비교
- 감독 총평 5줄, 전환점, 결정 평가와 다음 경기 처방 제공
- 맨 앞의 「이 경기의 한 수」가 실제 결정 하나의 시각과 내용을 크게 표시
- 여러 결정의 ±%p는 한 수의 단독 효과가 아니라 전체 판단 묶음이라고 명시
- 개입하지 않은 경기는 존재하지 않은 한 수를 만들지 않고 `개입 없음` 표시
- 기록에 없는 슈터·도움·xG·패스 경로는 추측하지 않음

### 6. 검증된 국면 5개 — 전부 전반·후반을 갖는다

**모든 국면이 전반판과 후반판을 함께 갖고 플레이어가 고른다.** 국면
카드에 버튼이 둘이다.

```
전반   22:00 급수 타임 ─ 3분 ─▶ 25:00 재개 ─ 22분 ─▶ 47:00 전반 종료
후반   67:00 급수 타임 ─ 3분 ─▶ 70:00 재개 ─ 22분 ─▶ 92:00 경기 종료
```

- 시작 분과 반은 **국면 데이터에 없다.** 같은 국면이 두 시각을 가지므로
  적을 수 없다. 단일 원본은 **`src/matchClock.ts`** 이고, **거기 밖에서
  45·90·22를 직접 쓰지 마라.**
- 경기 길이는 언제나 750틱이다. 이 파일은 그 750틱에 몇 분이라고 이름을
  붙일지만 정하므로 **밸런스와 무관하다.**
- 전반을 고르면 종료 화면에 **하프타임 주장 정리**가 붙는다
  (`src/analysis/halftime.ts`). 실제 기록만 말하고 명령하지 않는다.
- 전반이 끝난 것은 **"전반 종료"** 이지 경기 종료가 아니다.

### 6-2. 상대 팀 선택 — 2026-07-30 (난이도 3단계를 대체했다)

킥오프 전에 오늘 만날 상대를 고른다. **FIFA 순위를 참고한 실제 국가 열세
팀**이며 팀마다 하는 축구가 다르다. 쉬움·보통·어려움 3단계는 **없어졌다** —
세기만 다른 같은 팀이라 무엇을 골라도 대응이 똑같았기 때문이다.

- 단일 원본은 `src/sim/constants.ts` 의 `OPPONENTS` 이고, 화면·주장·
  보고서가 `src/analysis/opponents.ts` 를 통해 그 값을 읽는다.
- **선수 개인 이름은 여전히 넣지 않는다.** 불변식 3번은 팀이 아니라
  선수에 대한 것이다 — 실점 공식이 가장 느린 수비수를 기계적으로 지목하기
  때문이다. 엠블럼·유니폼 이미지도 저작권 때문에 안 쓴다.
- 난수를 하나도 더 안 쓴다. 순수 함수 `applyOpponent` 가 이미 뽑아둔
  난수와 비교되는 계수만 곱한다.
- **기준팀은 미국(16위)이고 계수가 전부 1.0이라 완전한 항등이다.**
  다섯 국면의 합격 기준선은 언제나 기준팀에서만 잰다.
- 세기를 **공격력과 수비력으로 나눈 것**이 이 표의 핵심이다. 눈금 하나만
  두면 아래 순위 팀이 위협도 적고 뚫기도 쉬워서 지키는 국면이 사라진다.
- `shape` 는 위협의 크기가 아니라 **모양**이다. 브라질은 배후 비중이
  스페인의 두 배가 넘어 라인을 올리면 뚫린다. 팀마다 답이 다르다.
- `npm run sim` 은 기준팀만, `npm run sim -- --team=ALL` 이 열세 팀을 잰다.

### 7. 선수 자유 위치 배치

이번 Codex 작업의 핵심이다. 사용자가 기존 드래그를 다시 문제 삼았고,
QA 결과 단순 버그가 아니라 **요구를 잘못 정의한 것**으로 확인됐다.

수정 전:

- 위로 끌면 `PUSH_UP`, 아래로 끌면 `DROP_BACK`
- 가로·빈 공간·같은 줄 이동은 원위치 또는 화면 전용 자리 교환
- 전용검사 28개와 이전 QA도 이 제한을 정상 동작으로 고정
- 따라서 검사에 모두 통과해도 “원하는 위치에 놓기”는 존재하지 않았음

수정 후:

- `PlayerPosition { x, y }`, `PlayerState.position`,
  `POSITION { target, position }` 결정 추가
- x는 우리 골문 0 → 상대 골문 105, y는 터치라인 0 → 68
- 드롭 좌표가 실시간 상태·결정 재현·중앙 경기장·종료 뒤 150판 분석에
  같은 값으로 반영
- 카드가 겹치면 44px 표적을 보존하는 가까운 빈자리로만 최소 보정
- 골키퍼·피치 밖·수비 셋 미만은 `checkPosition()` 한 곳에서 차단
- 새 포메이션을 고르면 모든 자유 좌표를 `null`로 만들고 전체 재배치
- 교체로 나가거나 들어오는 선수도 자유 좌표 초기화
- 직접 위치는 `PUSH_UP`·`DROP_BACK`을 풀고, 둘을 새로 걸면 자유 위치 삭제
- `HOLD`·`BACK_OFF`·`CONSERVE`는 자유 위치와 함께 유지 가능

자유 위치는 화면 장식이 아니다.

- 전진하거나 측면으로 벌리면 우리 공격 기회와 상대 역습 위험이 함께 증가
- 후퇴하거나 중앙을 채우면 둘이 함께 감소
- 한 선수 극단 배치 약 4%, 여러 선수 누적 24% 상한
- 직접 배치가 0명이면 기존 계수 객체를 그대로 반환해 저장된 결과와
  매 틱 난수 18개 소비 순서를 보존
- 숫자 단일 원본은 `src/sim/constants.ts`의 `FREE_POSITION`

주요 파일:

- 계약·검증·재현: `src/sim/types.ts`, `src/sim/engine.ts`
- 확률 영향: `src/sim/tactics.ts`, `src/sim/constants.ts`
- 중앙 경기장: `src/render/visual.ts`
- 드롭 좌표·충돌: `src/ui/squadDrag.ts`
- 화면·3×3 버튼: `src/ui/SquadPanel.tsx`

## 에이전트 역할 — 넷 다 Codex·Claude Code 양쪽에서 쓴다

| 에이전트 | 역할 | 코드를 고치나 |
|---|---|---|
| 게임 | 축구 규칙·엔진·관전 연출·밸런스 | 고친다 |
| QA | 브라우저로 끝까지 검사하고 숫자로 보고 | **절대 안 고친다** |
| UX/UI | 웹 정보 구조·조작·반응형 | UI만 고친다 |
| Coach | 경기 종료 원인 분석과 처방 | 분석 영역만 고친다 |

**지침의 단일 원본은 `docs/agents/<이름>.md` 하나다.** 플랫폼별 실행
파일은 그 원본을 읽으라고만 적혀 있는 얇은 파일이다.

| | Claude Code | Codex |
|---|---|---|
| 실행 파일 | `.claude/agents/<이름>.md` | `.codex/agents/<이름>.toml` |
| 부르는 이름 | `game-agent` 처럼 하이픈 | `game_agent` 처럼 밑줄 |

**역할을 바꿀 때는 `docs/agents/` 의 공통 원본만 고친다.** 실행 파일에
내용을 복사하면 한쪽만 수정되어 서로 다른 에이전트가 된다.

동시에 여러 개를 돌릴 때 주의: **QA 는 코드를 안 고치므로 언제나 안전**
하지만, 게임과 UX/UI 는 둘 다 화면을 만질 수 있어 같이 돌리면 충돌한다.

## 절대 바꾸면 안 되는 불변식

1. `src/sim/`에서 브라우저 API·`Date`·`Math.random`을 사용하지 않는다.
2. `drawTick()`의 난수 18개와 순서를 바꾸지 않는다.
3. 실존 선수 이름·사진·구단 데이터를 넣지 않는다.
4. 확률 숫자는 `src/sim/constants.ts`에만 둔다.
5. 관전 연출이 시뮬 결과를 바꾸지 않는다.
6. 국면 추가는 `src/data/problems.json`만으로 가능해야 한다.
7. 작동하지 않는 버튼이나 휴대폰에서 누를 수 없는 조작을 만들지 않는다.

## 아직 해야 할 것

**남은 것은 코드가 아니라 제출물이다.** 1·2번은 없으면 **결격**이고,
2번은 1번이 끝나야 찍을 수 있다. 3·4·5번보다 먼저 처리하라.

1. **배포 URL 만들기**(8번) — 사용자가 7/31에 하기로 결정
2. **시연영상 유튜브 링크**(9번) — 필수 제출물, 아직 없음. 대본은
   `docs/demo-video.md`
3. 베트남의 위 두 쉬운 국면을 허용할지 한 번 결정한 뒤 8/1 저녁 숫자 동결
4. 첫 15초 온보딩
5. 최종 버그 점검과 최종 배포

다음 작업자는 자유 배치를 다시 `PUSH_UP`·`DROP_BACK` 두 개로 축소하거나
화면 전용 자리 교환을 복구하면 안 된다. 기능 변경 전
`docs/worklog.md`의 “상하 지시 드래그를 실제 자유 좌표로 바꿨다”와
`docs/qa-log.md`의 QA-06을 먼저 읽는다.

알고 있지만 미룬 축구 사실성 문제와 측정값은 `docs/HANDOFF.md`의
“아직 축구로 안 보이는 것”과 “알면서 안 고친 것”을 읽는다. 이미 해결된
문제를 다시 보고하거나 근거 없이 튜닝하지 않는다.

## 커밋과 종료 절차

IDE에서 **Changes**와 **Staged Changes**를 구분해 확인하고, 필요한 파일만
스테이징한다. 커밋 메시지는 `AGENTS.md`의 규칙을 따른다.

```text
type: 명령문 제목

무엇을 바꿨는지와 왜 필요한지를 설명하는 본문.
본문은 영문 기준 72자마다 줄바꿈한다.
```

사용 유형: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

끝나면 반드시:

1. 관련 검사 실행
2. `docs/progress.md` 갱신
3. `docs/HANDOFF.md` 갱신
4. 필요하면 이 문서도 갱신
5. 한국어 제목의 규칙형 커밋 작성
6. 즉시 푸시
