# 축구 사활 — 설계 명세

> 작성 2026-07-27 · 개발 2026-07-28 ~ 08-02 · 제출 2026-08-03 10:00

바둑 사활문제를 축구로 옮긴 **실시간** 전술 퍼즐. 창작된 경기 국면 하나를 주고 75초 안에 풀게 한다.

---

## 0. 이 문서를 관통하는 결정 5개

이 다섯 개가 나머지 전부를 결정한다. 여기가 흔들리면 다시 짜야 한다.

| # | 결정 | 이유 |
|---|---|---|
| 1 | **시뮬레이션 코어와 화면을 완전히 분리한다** | 같은 경기를 화면 없이 여러 번 돌려야 경기 분석 화면과 자동 검증이 성립한다 |
| 2 | **모든 국면은 "앞 감독이 잘못 걸어놓은 지시"를 물려받는다** (`initialTactics`) | 중립에서 시작하면 아무것도 안 해도 통과한다. 퍼즐 성립의 전제 |
| 3 | **순서가 의미를 갖는 것은 레버가 아니라 교체 카드다** | 레버는 확률에 곱하는 승수라 곱셈 순서가 없다. 카드는 회수 불가라 순서가 실재한다 |
| 4 | **데이터는 전부 가상이다** | 실존 인물·팀 미사용. 숫자를 퍼즐이 성립하도록 자유롭게 정할 수 있다 |
| 5 | **밸런스는 사람이 아니라 봇이 판정한다** | 27조합 × 5국면 = 135판을 1초 안에 돌린다. 손으로는 8시간 걸린다 |

## 1. 무엇을 만드는가

### 1.1 한 판의 모습

> 후반 80분, 1-0으로 이기고 있는데 우리 팀 한 명이 퇴장당했다. 교체 카드 2장.
> 앞 감독은 이미 라인을 끝까지 내리고 압박을 풀어놓았다. **이 판을 지켜낼 수 있는가.**

- 실시간 **75초** (게임 내 15분을 12:1로 압축, 10Hz × 750틱)
- 일시정지 없음. 되돌리기 없음. 교체 카드는 회수 불가
- 국면당 전술 레버 3개 노출 + 교체 카드 0~3장

### 1.2 설계 원칙 4개

| 원칙 | 구현 | 이 원칙이 없으면 |
|---|---|---|
| 시계는 멈추지 않는다 | 일시정지 부재. 10Hz 고정 틱 | 분석가의 경험이 된다 |
| 자원은 유한하다 | 교체 카드 회수 불가. 레버는 체력·공간 비용 발생 | 모든 좋은 수를 다 두게 되어 판단이 소멸 |
| 되돌릴 수 없다 | 실행 취소 없음. 종료까지 관전 강제 | 시행착오 반복으로 긴장 소멸 |
| 정보는 불완전하다 | 상대 내부 수치 미공개. 관찰 지표로만 추론 | 최적화 문제가 되어 옵티마이저의 경험이 된다 |

### 1.3 결과와 판단을 분리해서 채점한다

축구는 확률 게임이라 옳게 판단하고도 무너진다. 그래서 **이진 결과**(지켜냈다/무너졌다)와 **감독 평점**(개입이 만든 기대값 변화량)을 따로 매긴다.

이 구조에 의해 **"무너졌지만 명장"**과 **"지켜냈지만 오판"**이 성립한다. 운으로 진 판에서도 납득이 생기고, 운으로 이긴 판에서도 재도전 동기가 생긴다.

## 2. 아키텍처

```
src/
├─ sim/                    순수 함수 시뮬레이션 코어 — 표현 계층에 비의존
│   ├─ rng.ts              mulberry32. 경기용/연출용 스트림 분리
│   ├─ types.ts            MatchState · Decision · Problem 타입
│   ├─ constants.ts        기본 확률·승수표 (동결 대상)
│   ├─ tactics.ts          레버 3축 → 계수 변환
│   ├─ opponent.ts         상대 성향 도출 및 전환
│   ├─ events.ts           경고·퇴장·부상·페널티·추가시간
│   └─ engine.ts           tick(state, inputs) → state
├─ render/
│   ├─ pitch.ts            Canvas 2D 피치·선수·볼
│   └─ interpolate.ts      10Hz 상태 → 60fps 보간
├─ ui/                     React. 스코어보드·레버·벤치·지표·코멘터리
├─ analysis/               경기 분석 — 병렬 재생·기대값 델타·평점
└─ data/
    ├─ problems.json       국면 5종
    ├─ squads.json         선수 (전부 가상)
    └─ commentary.json     중계 문장

balance/                   Node 전용. 브라우저 없이 실행
├─ bots.ts                 정책 봇
├─ sweep.ts                27조합 전수 스윕
└─ verify.ts               합격 판정 + 보고서 출력
```

**핵심 제약: `sim/`은 `render/`·`ui/`를 import 하지 않는다.** 브라우저 API(`window`, `document`, `requestAnimationFrame`)를 참조하지 않는다. 그래야 Node에서 그대로 돌아간다.

### 2.1 왜 분리하는가

1. **경기 분석 화면이 성립한다.** 같은 시드로 정답 경로와 내 선택을 각각 돌려야 하는데, 계산이 화면에 묶여 있으면 두 번째 경기를 돌릴 자리가 없다.
2. **밸런싱이 8시간에서 1분으로 줄어든다.** 400시드 × 27조합을 손으로 하면 불가능하다.
3. **버그가 격리된다.** 렌더가 깨져도 경기는 계속 굴러간다.

### 2.2 결정론 — 분석 화면의 전제 조건

```ts
rngMatch  = mulberry32(problem.seed)                  // 경기 판정 전용
rngVisual = mulberry32(problem.seed ^ 0x9E3779B9)     // 연출 전용

// 저장하는 것은 결과가 아니라 결정 이력
type Decision =
  | { tick: number; type: 'LINE'  | 'PRESS' | 'WIDTH'; value: 0 | 1 | 2 }
  | { tick: number; type: 'SUB';  out: string; in: string }

replayUser     = simulate(seed, userDecisions)
replaySolution = simulate(seed, problem.solutionDecisions)
```

**규칙 3개 (어기면 재현이 조용히 깨진다)**
1. 시드는 국면에 고정한다. `Date.now()` 기반 시드 금지.
2. **난수 소비 순서를 고정한다.** 조건 분기 안에서 난수를 뽑지 않는다. 매 틱 정해진 슬롯 순서로 뽑고, 필요 없으면 버린다.
   순서: `[배후, 전진시도, 진입성공, 슛결과, 상대오픈, 상대슛결과, 세트피스, 파울, 카드, 부상]` — 10슬롯 고정
3. 렌더용 난수는 별도 스트림에서 뽑는다. 연출을 고쳐도 경기 결과가 변하지 않아야 한다.

## 3. 엔진 명세

| 항목 | 사양 |
|---|---|
| 좌표계 | 105 × 68 (실제 피치 미터). 렌더 해상도와 분리 |
| 틱 | 10Hz 고정 (100ms). 렌더는 rAF로 분리, 상태 보간 |
| 총 틱 | **750틱 고정.** 추가시간도 이 안에서 처리(별도 가산 없음) |
| 시간 압축 | 게임 내 15분 → 실제 75초 (12:1) |
| 구역 모델 | 3레인 × 3서드 = 9구역. 볼 소유는 구역 단위, 선수는 연속 좌표 |
| 탭 이탈 | `delta` 상한 100ms. 백그라운드 복귀 시 점프 차단 |

### 3.1 상태 벡터

```ts
interface MatchState {
  tick: number                    // 0 ~ 749
  score: [number, number]         // [우리, 상대]
  ball: { zone: number; owner: 'HOME' | 'AWAY' | null; x: number; y: number }
  tactics: { line: 0|1|2; press: 0|1|2; width: 0|1|2 }   // 0=낮음/약/좁게
  players: PlayerState[]          // 22명
  subsLeft: number
  opponent: { mentality: 'PARK_BUS' | 'BALANCED' | 'ALL_OUT'; pendingShift: number | null }
  metrics: { attack: number; possession: number; danger: number }  // 지표 바 3종
  log: CommentaryEntry[]
}
```

### 3.2 tick 한 번에 일어나는 일

```
1. 체력 소모      stamina -= drainBase × pressMult × (1 + 0.15 × lineHigh)
2. 상대 성향 갱신  스코어 + 인원 → mentality (전환 예고가 있으면 카운트다운)
3. 우리 공격      전진 시도 판정 → 진입 성공 판정 → 슛 결과 판정
4. 상대 공격      배후 침투 / 오픈플레이 / 세트피스 3채널 각각 판정
5. 사건 판정      파울 → 경고 → 퇴장 / 부상
6. 지표 갱신      최근 100틱 이동평균으로 지표 바 3종
7. 코멘터리       트리거 조건 충족 시 문장 1줄 추가
```

## 4. 확률 모델

기획서에는 승수(`×1.30`)만 있고 곱할 원본이 없었다. 그 원본을 여기서 정의한다.

### 4.1 기본 확률 (틱당) — 전부 초기값. 봇 검증으로 조정한 뒤 8/1 저녁 동결

```ts
// 발생 빈도
const A0 = 0.0180   // 우리 전진 시도        750틱 → 13.5회
const O0 = 0.0110   // 상대 전진 시도        750틱 →  8.3회
const B0 = 0.0020   // 상대 배후 침투 시도   750틱 →  1.5회
const S0 = 0.0060   // 세트피스 획득         750틱 →  4.5회

// 시도가 실제로 위협이 될 확률 — 이게 없으면 시도 횟수만 있고 결과가 없다
const P_ENTER      = 0.35   // 전진 시도 → 슈팅 상황 도달
const P_ENTER_OPP  = 0.35   // 상대도 동일. 개방도 승수로 갈린다
```

**무개입 기준 기대 득점 (라인 보통 · 압박 중 · 폭 보통, BALANCED 상대)**

| | 계산 | 기대 골 |
|---|---|---|
| 우리 | 13.5 × 0.35 × 슛선택 × xG | ≈ 0.42 |
| 상대 오픈 | 8.3 × 0.35 × 슛선택 × xG | ≈ 0.26 |
| 상대 배후 | 1.5 × 0.75 × 0.185 | ≈ 0.21 |
| 상대 세트피스 | 4.5 × 0.035 | ≈ 0.16 |
| **합계** | | **≈ 1.05골 / 15분** |

**검증 기준: 무개입에서 양 팀 합계 0.9~1.4골.** 실제 축구(15분 ≈ 0.7골)보다 약간 높게 잡는다. 75초 안에 아무 일도 안 일어나면 게임이 아니다.

**라인을 낮추면 실제로 손해인지 확인 (국면 2·4의 반전이 여기 걸려 있다)**

| | 배후 | 세트피스 | 우리 득점 | 순 득실 |
|---|---|---|---|---|
| 라인 보통 | 0.21 | 0.16 | 0.42 | **+0.05** |
| 라인 낮음 | 0.09 | **0.44** | 0.29 | **−0.24** |

세트피스 승수(낮음 ×2.80)가 배후 절감(×0.45)을 압도해야 "잠글수록 맞는다"가 성립한다. **이 두 숫자의 비율이 게임 전체에서 가장 중요하다.** 봇 검증에서 가장 먼저 확인할 항목이다.

### 4.2 슈팅 기대값 (xG)

| 상황 | xG | 슈팅 선택 확률 |
|---|---|---|
| 진입 성공 · 박스 중앙 | 0.120 | 0.42 |
| 진입 성공 · 박스 측면 | 0.052 | 0.30 |
| 진입 실패 · 박스 외곽 | 0.031 | 0.22 |
| 배후 침투 성공 (일대일) | 0.185 | 0.75 |
| 세트피스 | 0.035 | 1.00 |
| 페널티킥 | 0.760 | 1.00 |

골키퍼 실력은 위 xG에 이미 포함된 것으로 본다. 별도 계수를 두지 않는다.
마무리 능력: `xG × finishing` (0.7 ~ 1.3), 슈터는 해당 구역 최근접 공격수.

### 4.3 전술 레버 승수

**수비라인 (line: 0 낮음 / 1 보통 / 2 높음)**

| | 배후 침투 | 볼 탈취 | 체력 소모 | 진입 xG | **세트피스** |
|---|---|---|---|---|---|
| 높음 | ×2.20 | ×1.25 | ×1.15 | **×1.30** | ×0.60 |
| 보통 | ×1.00 | ×1.00 | ×1.00 | ×1.00 | ×1.00 |
| 낮음 | ×0.45 | ×0.80 | ×0.90 | ×0.70 | **×2.80** |

> **세트피스 열이 이 게임에서 가장 중요한 숫자다.** 이것이 없으면 라인 낮음이 배후 침투를 ×0.45로 깎기만 해서 전 국면에서 지배 전략이 되고, "잠글수록 더 맞는다"가 원리적으로 불가능해진다. 축구 상식과도 맞는다 — 깊이 내려앉으면 걷어내고, 걷어내면 코너를 준다. 화면에서는 **코너 횟수**로 즉시 읽힌다.
>
> **진입 xG ×1.30**은 기획서의 "공격 시작점 +12m"를 배선한 것이다. 이것이 없으면 라인의 최적값이 전 국면에서 '보통'으로 수렴해 축이 죽는다.

**압박 강도 (press: 0 약 / 1 중 / 2 강)**

| | 볼 탈취 | 체력 소모 | 상대 오픈 | 파울 |
|---|---|---|---|---|
| 강 | ×1.40 | **×1.80** | ×0.80 | ×1.50 |
| 중 | ×1.00 | ×1.00 | ×1.00 | ×1.00 |
| 약 | ×0.70 | ×0.65 | ×1.25 | ×0.80 |

**수비 폭 (width: 0 좁게 / 1 보통 / 2 넓게) — 공격 진입 "횟수"에 건다**

```ts
// 반드시 슛 구역표가 아니라 전진 시도 횟수에 곱한다.
// 구역 재분배로 표현하면 골문 앞 중앙이 측면보다 3배 값비싸서 '좁게'가 이겨버린다.
K_width = {
  넓게: 1.05 + 0.30 × 상대밀집도,   // 밀집도 1.0 → ×1.35
  보통: 1.00,
  좁게: 0.95 - 0.20 × 상대밀집도,   // 밀집도 1.0 → ×0.75
}
// 수비 쪽: 좁게 → 중앙 차단 ×1.40 · 측면 노출 ×1.35 / 넓게 → 그 반대
```

> **폭이 국면 간 정답의 부호가 뒤집히는 유일한 축이다.** 상대가 뭉쳐 있을 때(밀집도 높음)만 '넓게'가 강력하다. 지키는 판에서는 상대가 올라와 있어 밀집도가 낮으므로 자동으로 '좁게'가 유리해진다. 하나의 계수로 두 방향이 나온다.

### 4.4 상대 성향 — 스코어에서 도출한다

**성향은 국면 데이터에 직접 쓰지 않는다. 매 틱 스코어와 인원에서 계산한다.** 그래야 경기 중 스코어가 바뀌면 상대도 바뀐다.

```ts
function mentality(state) {
  const diff = state.score[1] - state.score[0]   // 상대 기준 득실
  if (diff < 0) return 'ALL_OUT'                 // 상대가 지고 있다 → 올라온다
  if (diff > 0) return 'PARK_BUS'                // 상대가 이기고 있다 → 내려앉는다
  return 'BALANCED'
}
```

| 성향 | 오픈 볼륨 | 배후 위협 | 우리 진입 개방도 | 밀집도 |
|---|---|---|---|---|
| ALL_OUT | ×1.35 | ×1.30 | ×1.40 | 0.10 |
| BALANCED | ×1.00 | ×1.00 | ×1.00 | 0.50 |
| PARK_BUS | ×0.70 | ×0.55 | ×0.60 | 1.00 |

상대 10명 보정: 오픈 볼륨 ×0.75, 밀집도 +0.30 (상한 1.0)
우리 10명 보정: 커버 공백 계수 — 상대 전 채널 ×1.22

**전환 예고 (TELEGRAPH).** 성향이 바뀌기 40틱(4초) 전에 코멘터리 1줄 + 상대 벤치 하이라이트. 예고가 없으면 반응이 4~6초 늦고 그 지연만으로 결과가 크게 갈린다. 심사자가 딱 한 판 한다는 전제에서 이건 선택이 아니다.

### 4.5 체력

```ts
drainBase = 0.030          // 틱당. 750틱 × 0.03 = 22.5 소모
effective(attr) = attr × (0.55 + 0.45 × stamina / 100)
if (stamina < 35) effective *= 0.85     // 절벽
```

> **절벽이 필요한 이유**: 소모가 선형이면 압박 강의 이득과 비용이 정확히 상쇄되어 압박 축이 평평해진다. 절벽을 붙여야 압박의 비용이 볼록해지고 "지금은 강하게, 나중엔 풀어야" 하는 판단이 생긴다.

### 4.6 사건

| 사건 | 조건 | 확률 |
|---|---|---|
| 파울 | 압박 승수 적용 | `0.0025/틱 × pressFoul` |
| 경고 | 파울 발생 시 | 0.18 |
| **퇴장** | 경고 보유 + 압박 강 | `0.00025/틱` (750틱 누적 ≈ 17%) |
| 페널티 | 자기 진영 박스 내 파울 | 파울의 0.08 |
| 부상 | 지정 틱 강제, 또는 체력 < 25 | `0.0004/틱` |
| 골 후 재개 | 실점 팀이 중앙에서. 900ms 정지 연출 | — |

> **퇴장 해저드가 압박 축이 값을 갖는 유일한 통로다.** 경고 보유 선수가 있는 국면에서만 발동하고, "압박을 올리고 싶은데 올리면 안 되는" 긴장을 만든다.
>
> **골 후 재개는 반드시 넣는다.** 이게 없으면 첫 실점 순간 경기가 이어지지 않는다. 그리고 실점은 승패를 가르는 유일한 사건인데 전용 연출이 없으면 심사자가 자기가 졌다는 걸 75초 끝나고서야 안다.

## 5. 교체 카드 — 순서가 실재하는 유일한 장치

**레버는 확률에 곱하는 승수다. 곱셈에는 순서가 없다.** `2×3×5`나 `5×2×3`이나 30이다. 그래서 레버를 어떤 순서로 당기든 결과가 같은 것은 계산 문제가 아니라 설계상 필연이다.

**카드는 다르다.** 3장뿐이고 회수가 안 된다. 되돌릴 수 없는 자원이라 쓰는 순서가 진짜로 의미를 갖는다.

### 5.1 순서가 값을 갖게 하는 장치 3개

| 장치 | 규칙 | 효과 |
|---|---|---|
| **선행 조건** | 느린 수비수를 뺀 뒤에 라인을 올려야 안전하다. 반대로 하면 그 사이 배후 실점 위험이 `×2.20` 걸린다 | 카드 → 레버 순서가 값을 갖는다 |
| **강제 소모** | 부상은 카드 1장을 강제로 뺏는다. 먼저 다 써버리면 대응 수단이 없다 | 카드를 아끼는 판단이 생긴다 |
| **반영 지연** | 교체는 다음 데드볼에 반영된다 (최대 60틱) | 늦게 쓰면 늦게 듣는다 |

### 5.2 조작 — 폰에서 반드시 되어야 한다

심사자 상당수가 폰으로 연다. 지름 20px 원 위에 카드를 정확히 떨어뜨리는 건 손가락으로 불가능하다. 규칙상 **작동하지 않는 기능은 평가에서 제외**되므로 여기서 막히면 게임의 절반이 채점에서 빠진다.

**기본 조작: 2단계 탭.**
1. 벤치 카드를 탭 → 카드가 들리고, 교체 가능한 선수의 원이 커지며 강조된다
2. 나갈 선수를 탭 → 교체 실행

- 원의 실제 터치 영역은 시각적 크기와 무관하게 **최소 44 × 44 px**로 잡는다
- 드래그도 함께 지원한다(데스크톱에서 자연스러움). Pointer Events 단일 코드로 처리
- 잘못 탭하면 빈 곳을 탭해서 취소. 교체 실행 전까지는 되돌릴 수 있다

## 6. 국면 5종

**모든 국면은 `initialTactics`를 물려받는다.** 앞 감독이 이미 걸어놓은 지시다. 중립에서 시작하면 아무것도 안 해도 통과해버려 퍼즐이 성립하지 않는다. 이 필드 하나가 다섯 국면 전부의 성립 조건이다.

### 국면 1 — 「길이 막혔다」

| | |
|---|---|
| 상황 | **0-1 지고 있음 · 후반 70분 · 11 v 11** |
| 목표 | 동점 이상 |
| 카드 | 3장 |
| 노출 레버 | 라인 · 압박 · 폭 |
| 물려받은 지시 | 라인 보통 / 압박 중 / **폭 좁게** — 중앙 돌파를 시도하다 막힌 상태 |
| 상대 | 이기고 있으므로 PARK_BUS. 밀집도 1.0 |

**직관** 사람을 더 앞으로, 더 가운데로 몰아넣는다.
**정답** 몰아넣지 마라. 상대는 이미 골문 앞에 여덟을 세워놨고 거기 우리를 더 얹는 건 자리를 없애는 짓이다. **좌우로 벌려야 길이 난다.** 라인은 올려도 안전하다 — 상대가 내려앉아 뒷공간을 쓸 사람이 없다.

**승부처 2개**
1. 폭을 넓게 (밀집도 1.0이라 효과 최대)
2. 느린 수비수를 먼저 교체하고 → 그다음 라인을 올린다. 순서를 뒤집으면 그 사이 배후를 내준다

### 국면 2 — 「잠긴 문」

| | |
|---|---|
| 상황 | **1-0 이기고 있음 · 후반 70분 · 11 v 11** |
| 목표 | 리드 지키기 |
| 카드 | 3장 |
| 노출 레버 | 라인 · 압박 · 폭 |
| 물려받은 지시 | **라인 낮음 / 압박 약 / 폭 좁게** — 전부 잠가놓은 상태 |
| 상대 | 지고 있으므로 ALL_OUT |
| 특이 | 수비형 미드필더 1명이 **경고 보유** |

**직관** 1-0이니 그대로 내려앉아 버틴다.
**정답** **잠금을 푼다.** 깊이 내려앉을수록 걷어내게 되고, 걷어낼수록 코너를 준다. 라인을 보통으로 되돌리는 것만으로 세트피스 피격이 절반 이하로 떨어진다.

**승부처 2개**
1. 라인을 보통으로 되돌린다 (세트피스 회피)
2. 경고 보유 선수를 상대가 전원 공격으로 바뀌기 **전에** 교체한다. 방치하면 퇴장 → 즉시 붕괴

**난이도** 가장 쉽다. 첫 국면으로 배치한다.

### 국면 3 — 「욕심의 값」

| | |
|---|---|
| 상황 | **1-1 · 후반 80분 · 11 v 11** |
| 목표 | **무승부 또는 승리 둘 다 통과** |
| 카드 | 2장 |
| 노출 레버 | 라인 · 압박 · 폭 |
| 물려받은 지시 | **라인 높음 / 압박 강 / 폭 넓게** — 앞 감독이 이기려고 전부 올려놓은 상태 |
| 상대 | BALANCED |
| 특이 | **주전 3명의 체력이 이미 30대** (절벽 직전) |

**직관** 이기려고 올려놨으니 그대로 밀어붙인다.
**정답** **되돌려서 안정시킨다.** 체력이 절벽 아래라 압박 강을 유지하면 실효 능력이 붕괴하고 역습을 맞는다. 무승부도 통과인데 지는 위험을 지고 있는 상태다.

**이 국면만의 것** 다섯 중 유일하게 **리스크 수준을 플레이어가 정한다.** 안전하게 되돌려 무승부를 확보할 수도, 체력을 태워 승리를 노릴 수도 있다. 승리 시 평점에 가산.

> 이 국면은 물려받은 지시가 없으면 성립하지 않는다. 중립에서 시작하면 무승부가 목표이므로 아무것도 안 하는 것이 이미 최적이 된다. 전면 공세를 물려받아야 "가만히 두면 진다"가 성립한다.

### 국면 4 — 「한 명이 없다」

| | |
|---|---|
| 상황 | **1-0 이기고 있는데 우리 팀 퇴장 · 후반 80분 · 10 v 11** |
| 목표 | 리드 지키기 |
| 카드 | 2장 |
| 노출 레버 | 라인 · 압박 · 폭 |
| 물려받은 지시 | **라인 낮음 / 압박 약 / 폭 좁게** — 퇴장 직후 반사적으로 전부 내린 상태 |
| 상대 | 지고 있고 수적 우위. ALL_OUT |
| 특이 | 경고 보유 1명. 커버 공백 계수 ×1.22 |

**직관** 한 명 부족하고 1-0이니 전부 내려서 잠근다.
**정답** **내려앉는 순간 코너를 헌납하기 시작하고, 상대는 그걸 보고 전원을 올린다.** 라인은 가운데로 되돌리고, 좁히는 것만 한다. 압박은 올리지 않는다 — 퇴장 한 번이면 열세가 두 배가 된다.

**국면 2와 같은 교훈의 고난도판이다.** 자원이 없고(카드 2장, 10명) 상대가 더 강하다. 국면 2에서 배운 것을 더 어려운 조건에서 다시 쓴다.

### 국면 5 — 「한 명이 많은데 안 뚫린다」

| | |
|---|---|
| 상황 | **0-1 지고 있는데 상대 퇴장 · 후반 80분 · 11 v 10** |
| 목표 | 동점 이상 |
| 카드 | 2장 |
| 노출 레버 | 라인 · 압박 · 폭 |
| 물려받은 지시 | **라인 높음 / 압박 강 / 폭 좁게** — 흥분해서 중앙으로 몰아붙이는 상태 |
| 상대 | 이기고 있고 10명. PARK_BUS 극단. 밀집도 1.0 |

**직관** 상대가 열 명이니 전부 앞으로, 가운데로 몰아붙인다.
**정답** **열 명이 된 상대는 골문 앞에 더 촘촘히 선다. 사람을 더 모을수록 자리가 없어진다. 좌우로 벌려야 길이 난다.** 압박은 중으로 낮춰 체력을 아낀다 — 상대가 안 나오니 압박이 값을 못 한다.

**국면 1과 같은 교훈의 극단판이다.** 밀집도가 최고라 폭의 효과가 가장 크게 나온다.

### 6.1 정직하게 적어두는 한계

다섯 국면은 **두 개의 교훈**을 강도만 바꿔 반복하는 구조다.

- 「모을수록 좁아진다」 — 국면 1(중), 국면 5(강)
- 「잠글수록 맞는다」 — 국면 2(약), 국면 4(강)
- 국면 3만 별개 — 「욕심의 값」

**"다섯 개의 서로 다른 반전"이라고 홍보하지 않는다.** 대신 난이도 사다리로 배치한다: **2 → 1 → 3 → 4 → 5**. 쉬운 판에서 배우고 어려운 판에서 다시 쓴다. 국면마다 물려받은 지시가 다르므로 **출발점이 달라 과제 자체는 전부 다르게 느껴진다.**

## 7. 데이터 — 전부 가상

| 항목 | 처리 |
|---|---|
| 팀 이름 | **"우리 팀" / "상대"**. 실존 팀·국가명 미사용 |
| 선수 | **등번호 + 포지션만.** 이름 칸 자체를 만들지 않는다 |
| 능력치 | 전부 설계값. 목표 통과율에서 역산 |
| 이미지 | 사진·엠블럼·유니폼 **파일 0개.** 원형 + 등번호로만 표현 |
| 대회·경기 | 특정 대회를 지칭하지 않는다 |

이름이 없으므로 특정 선수 비하 문제가 원천적으로 발생하지 않는다. 판정·코멘터리 문구는 개인이 아니라 **상황·전술 단위**로만 서술한다.

### 7.1 선수 규모

- **우리 팀 11명 + 벤치 5명 = 16명 개별 정의**
- **상대 11명은 등번호·포지션·속도만.** 나머지는 포지션 평균 4종에서 상속
- 국면끼리 선수를 공유한다. 국면마다 다른 것은 시작 체력·경고 보유·이탈자뿐

### 7.2 표시 파라미터 4종

레버와 짝이 없는 데이터는 채택하지 않는다.

| 파라미터 | 범위 | 어느 레버와 짝인가 |
|---|---|---|
| 속도 | 0~100 | 라인 — 최저 속도 수비수가 배후 실점 확률을 직접 결정 |
| 체력 | 0~100 | 압박 — 강 압박 유지 시 실효 능력 붕괴 |
| 마무리 | 0.7~1.3 | 교체 — 득점이 필요한 국면의 투입 우선순위 |
| 상태 태그 | 경고/부상위험 | 교체 — 경고 보유 + 강 압박 시 퇴장 리스크 |

표기는 능력 평가가 아니라 **현재 상태**로 한다. "속도 58 (느림)", "78분 경과 · 체력 62".

## 8. 화면 3종

### 8.1 국면 선택

국면 카드 5장 — 제목 · 상황 한 줄 · 카드 수 · 난이도 · 최고 평점.
**최고 평점을 카드에 박아둔다.** "뒤늦음"으로 깬 국면은 "명장"으로 다시 깨고 싶어진다. 국면 개수를 늘리는 것보다 이게 훨씬 싸게 플레이 시간을 늘린다.

### 8.2 경기 (핵심)

```
┌─────────────────────────────────────┐
│  우리 팀  1 - 0  상대      교체 ●●○  78:24 │
├─────────────────────────────────────┤
│                                     │
│          피치 (화면의 60% 이상)          │
│        원 22개 + 볼 + 수비라인 표시         │
│                                     │
├─────────────────────────────────────┤
│  전방 침투 ▓▓▓░░  볼 소유 ▓▓░░░  피격 ▓▓▓▓░  │
├─────────────────────────────────────┤
│  라인 [낮음|보통|높음]  압박 [약|중|강]  폭 [...] │
├─────────────────────────────────────┤
│  78' 우측 뒷공간이 다시 열렸다              │
├─────────────────────────────────────┤
│  [15] [17] [19]  벤치 — 탭해서 교체        │
└─────────────────────────────────────┘
```

**3계층 피드백**

| 계층 | 지연 | 수단 |
|---|---|---|
| 즉시 | ≤0.3초 | 좌표 이동 · 수비라인 점선 이동 · 레버 상태 애니메이션 |
| 단기 | 3~5초 | 지표 바 3종 변동 · 코멘터리 갱신 |
| 결과 | 종료 시 | 기대값 델타 그래프 · 평점 · 승부처 공개 |

**아트 디렉션** 어두운 배경 위 진녹색 피치. 원형 + 등번호. 사진·엠블럼 전면 배제. 도형 언어가 저작권 제약과 정확히 일치하므로 **제약이 곧 스타일이 된다.**

### 8.3 경기 분석

- **동일 시드 병렬 재생** — 이 국면의 정답 경로 vs 나의 수. 승부처 앞뒤 5초를 3배속 반복
- 이진 판정 (지켜냈다 / 무너졌다)
- **감독 평점** 4등급
- 결정 시점별 기대값 델타 그래프
- 승부처 공개 + 다시 풀기

### 8.4 최초 15초 (심사자는 설명 없이 URL만 연다)

| 시점 | 처리 |
|---|---|
| 0.0초 | 국면 선택 화면 — 국면 카드 외 다른 요소 없음 |
| 0.5초 | 고스트 손가락이 벤치 카드 → 선수를 탭하는 동작 3초 루프 (텍스트 없음) |
| 진입 직후 | 킥오프 전 2초 정지 + 상황 카드 "1-0 · 후반 70분 · 교체 3장 · 지켜내라" |
| 킥오프+3초 | 무조작 시 **잘못 걸린 레버가 붉게 1회 점멸** |

> 마지막 항목이 중요하다. 물려받은 지시가 잘못됐다는 걸 알려주는 유일한 장치다. 이게 없으면 심사자는 레버를 건드릴 이유를 못 찾는다.

## 9. 판정 — 결과와 판단의 분리

**기대값 정의**: 각 틱의 `우리 득점 기대 − 상대 득점 기대`를 750틱 누적한 값. 순 기대값 델타 = `내 경기 누적 − 무개입 누적`.

| 등급 | 기준 | 문구 |
|---|---|---|
| 명장 | 델타 +0.35 이상 **그리고** 승부처를 올바른 순서로 포함 | 승부처를 정확히 짚었다 |
| 안정 | 델타 +0.15 ~ +0.35 | 합리적인 운영이었다 |
| 뒤늦음 | 델타 +0.15 미만, 또는 승부처는 짚었으나 순서 오류 | 방향은 맞았으나 타이밍이 늦었다 |
| 오판 | 델타 음수 | 이 개입이 위험을 키웠다 |

무개입 기준선은 국면 로드 시 한 번 계산해서 캐시한다.

## 10. 자동 검증

엔진이 순수 함수이므로 브라우저 없이 Node에서 돈다. 27조합 × 5국면 × 200시드 = 27,000판이 수 초 안에 끝난다.

| 봇 | 행동 | 합격 기준 |
|---|---|---|
| **A · 무개입** | 물려받은 지시 그대로 방치 | 통과율 **50% 이하** |
| **C · 정답 경로** | 승부처를 올바른 순서로 실행 | 통과율 **70% 이상** |
| **E · 전수 스윕** | 27조합 각각 고정한 채 완주 | 최고−최저 **20%p 이상** |

**A와 C의 격차가 20%p 이상**이면 그 국면은 합격이다. 미달이면 튜닝하지 않고 **목록에서 뺀다** (국면은 데이터이므로 비용 0).

> **봇 E를 반드시 넣는다.** 사전 분석에서 치명적 결함 세 개(만능 조합의 존재, 국면 간 정답이 안 뒤집힘, 지키는 국면의 무개입 통과율이 과도하게 높음)가 전부 이 스윕에서만 드러났다. A·C만으로는 전부 놓친다. 실행 시간은 1초 미만이다.

**조정 가능한 숫자를 국면당 4개로 못박는다.** 나머지는 전역 고정값으로 한 번 정하고 동결.
1. 물려받은 지시 (`initialTactics`)
2. 가장 느린 수비수의 속도
3. 시작 체력 3인분
4. 상대 성향 전환 시점

**파라미터 동결: 8월 1일(토) 저녁.** 이후 숫자에 손대지 않는다. 숫자를 하나 고치면 정답 경로와 측정한 통과율이 전부 무효가 되어 같은 작업을 다시 청구한다. 이것이 이 프로젝트의 가장 가능성 높은 실패 경로다.
